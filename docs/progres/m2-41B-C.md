1. 41B (HariUjian): stage 2 = `UjianCorak.mulai(player, sekte, null, (p, hasil) -> ...)`; null return = started, else the
   refusal Component. `hasil.skor()` is S2 0-1, `hasil.gagal()` true on fail (wilayah/teleport/tumbang/sumpah...),
   `hasil.alasan()` the reason key. The runner marks Sibuk `gabung.ujian` (batas + 200 ticks) and does NOT release it
   (41B owns it across stages). It sends `kirimUjian(tahap 0)` at the end: 41B sends its stage-3 HUD after. Bring the
   candidate to the foot of the stair before TUBUH (the stone is handed over where they stand). `UjianCorak.init()` is
   already called from `GabungEntities.register()` (idempotent; Masuk need not call it).
2. 41U-1 (HUD ujian): `gabung_ujian` data layout for tahap 2 is in the javadoc of `UjianCorak` (byte 0 = Corak ordinal,
   bytes 1.. per style, unsigned, "f" = 0-1 as 0-255). The trigram names (with symbols) are lang
   `kultivator.gabung.corak.trigram.0..7`, elements `kultivator.gabung.corak.unsur.0..4` (PilarQiEntity ids).
3. 41V-M (renderers): PilarQiEntity is now pickable (crosshair); DindingIlusi eyes carry their riddle trigram in
   `trigram()` (draw it once FLAG_TERINJAK, or always: designer's choice); walls with FLAG_TERUNGKAP show their trigram.
   Monk look key `biksu_perunggu` (LorongPerunggu.RUPA) needs a rupa in resep (`SosokApi.setRupa`).
4. 41V-P (fx/voice): no new voice lines from 41B-C (start/pass/fail voices stay with 41B: `gabung.ujian_mulai/lulus/
   gagal`). UjianFx can read the same HUD bytes.
